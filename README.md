# riptide

A multi-tenant document data lake. Companies upload internal documents; riptide
cleans, chunks and embeds them and serves **permission-aware** retrieval to any
LLM via a REST API and (later) an MCP server. Least privilege is the first
priority — a user only ever retrieves what their grants and clearance allow, and
cross-tenant leakage is treated as the worst possible bug.

> Orientation for contributors (human or AI) lives in **[CLAUDE.md](CLAUDE.md)**
> and, for the DB, in **[db/README.md](db/README.md)**.

## Stack

- **Python 3.12 · FastAPI** (API) · **arq** (Redis-backed job queue)
- **PostgreSQL 16 + pgvector** — one DB for metadata, ACLs, vectors and full-text
  search. `asyncpg` on the request path, `psycopg` for migrations.
- **Alembic** — migrations are the source of truth for the schema.
- **uv** — the only supported package manager. **Docker / compose** — the runtime.

## Quickstart (Docker)

```bash
docker compose up --build
```

This starts Postgres and Redis, runs the one-shot **migrate** service
(`alembic upgrade head`), then brings up the **api** and **worker** with hot
reload. The API is at http://localhost:8000 — try `/health`, `/docs`.

Seed a demo tenant and print working credentials:

```bash
PYTHONPATH=. uv run python scripts/seed_demo.py
# then, e.g.:
curl -H "X-API-Key: <printed key>" http://localhost:8000/documents
```

## Architecture

```
Upload → auth/policy check → store raw file (bronze) → enqueue →
executor → detect type → extract → CanonicalDoc (silver) → clean → chunk →
enrich (ACL snapshot, lineage) → embed → index (gold) → permission-aware retrieval
```

Current state: the **database + security model** are built and tested; the
ingestion pipeline and retrieval service are designed and upcoming. See
`diagrams/` for the ERD, data model and ingestion-pipeline diagrams.

### Security model (built)

- Multi-tenant via Postgres **Row-Level Security**. The app connects as
  least-privilege login roles (`riptide_api` / `riptide_worker`), never the owner
  or a superuser.
- Per request, `app.tenant_id` / `app.user_id` are set with `SET LOCAL` inside a
  transaction; a missing setting returns zero rows (**fail closed**).
- Permissions: collections are the boundary; grants are additive (no deny);
  clearance is a separate, non-inherited gate. Chunks carry an ACL snapshot so
  retrieval filters inside the query, before ranking.
- Authentication: API keys (prefix + peppered hash, constant-time verify) and
  session JWTs resolving to `(tenant_id, user_id)`.

## Testing

```bash
PGHOST=localhost PGUSER=postgres PGPASSWORD=postgres ./db/run_tests.sh
```

Rebuilds a throwaway DB via `alembic upgrade head` and runs 28 isolation /
permission / versioning / model-lifecycle tests (each proving both the allowed
and the denied path). Needs a Postgres with pgvector ≥ 0.8.

## Migrations

```bash
uv run alembic revision -m "describe change"   # write raw SQL in op.execute(...)
uv run alembic upgrade head
uv run alembic downgrade -1
```

Migrations are **hand-written raw SQL** — the schema's RLS policies, triggers,
functions and roles can't be autogenerated. After a schema change, add a test and
regenerate the ERD (`uv run python scripts/gen_erd.py`).
